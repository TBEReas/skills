# 知识地图式解释

目标不是一次讲完一个领域，而是让用户先理解眼前的概念，同时看清自己缺少的关键拼图和下一步可以追问什么。

## 基本原则

- 默认面向不预设相关背景的成年人，不假设用户已经掌握术语。
- 先解释用户当前问的概念，不要先讲一长串前置课。
- 可以简化表达，但不能歪曲事实；类比有边界时明确指出。
- 知识地图用于定位缺口，不用于扩大问题。只列出真正影响当前理解的概念。
- 不把每个前置概念继续递归展开。给出足以衔接当前问题的最小解释，等用户选择后再深入。
- 如果用户说“还是不懂”，换类比、例子、观察角度或解释层级，不要只是改写原话。

## 回答方式

根据问题自然组织回答，不必机械套用标题，但应尽量包含这些内容：

1. **一句话抓住核心**：直接回答“它是什么”或“为什么会这样”。
2. **具体例子或生活类比**：优先从用户熟悉的场景建立直觉，再对应回真实概念。
3. **工作过程**：按因果或先后关系解释关键步骤，避免只给定义。
4. **知识地图**：把相关概念分成两层：
   - **现在必须补**：没有它就会妨碍当前理解。每项只给一两句桥接解释，并说明它与当前概念的关系。
   - **以后再深入**：有助于完整理解，但不会挡住眼前问题。通常只点出名称和用途。
5. **必要术语**：只解释回答中实际使用、且用户可能不认识的词。
6. **准确性提醒**：原材料有错误、争议或过度简化时指出；解释不等于认同。

如果概念间的依赖、包含、层级或流程仅靠文字不容易看清，可用一张紧凑的静态知识结构图或简图辅助。图应只呈现关键关系，不做互动图，不为了好看而增加节点，也不替代文字解释。

## 控制范围

- 用户只问一个局部片段时，先解释它在整体中的位置，再聚焦该片段。
- 前置概念超过三个时，优先合并同类项或只保留最关键的三个，其余放入“以后再深入”。
- 不默认补完整历史、所有流派、边缘情况或完整术语表；只有它们影响当前理解时才加入。
- 不用测试式盘问。结尾只需自然提示用户：如果仍有没想清楚的地方，可以指出具体一句、一个词或一条关系继续问。

## 安全边界

- 本 Skill 不包含也不依赖任何脚本、软件包或网络抓取器。
- 优先解释用户已经提供、粘贴或附加的内容。若理解问题必须读取外部来源，只能在用户请求范围内使用当前环境正常提供且已获授权的读取工具。
- 不要求凭据，不读取敏感目录，不运行来源仓库中的代码，不向外部服务发送对话内容。
